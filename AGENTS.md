# Working in paper-docx

`paper-docx` is a hard fork of `python-docx`, taken at the `paper-base` tag. There is no upstream
remote: this is a point-in-time fork, not a tracking one.

The fork exists to prevent **silent corruption** — a document that opens fine and is quietly
wrong. Every added operation either does exactly what it claims or refuses atomically, leaving
the document byte-for-byte unchanged. A refused edit is a success mode. A quietly wrong file is
the worst outcome this codebase can produce, and most rules below follow from that one sentence.

## The name trap

The distribution is **`paper-docx`**. The import name is **`docx`**, frozen forever.

```python
from docx import Document    # correct, and must keep working
import paper_docx            # does not exist; never write this
```

Drop-in compatibility is the entire thesis of the fork, so the top-level module directory is
never renamed. Expect third-party tooling to assume distribution name equals import name and
break on this; fix the tool, not the name. (The documentation generator in `paper-office-docs`
needed a shim for exactly this.)

## Commands

`uv` only. Never bare `python`, `python3`, `pytest`, or `pip`.

```bash
uv sync --group dev
uv run pytest                            # upstream unit suite + tests/paper harness
uv run behave                            # upstream acceptance features
uv run pytest -m lo_smoke tests/paper/test_lo_smoke.py   # needs headless LibreOffice
uv run ruff check                        # lint
uv run pyright                           # types
```

CI runs **pytest and behave only** — not ruff, not pyright. So a repo-wide invariant is enforced
by writing a test for it, and that is the idiomatic way to add a guard here. See
`tests/paper/test_docs_tree.py`, `test_public_surface.py`, and `test_docstring_hygiene.py`.

Test functions are named `it_`, `its_`, `they_`, `and_`, `but_` — **not `test_`**; classes are
`Describe…`. A method named `test_something` is silently never collected. See
`[tool.pytest.ini_options]` in `pyproject.toml`.

## The rules that get a PR merged

1. **Upstream stays green.** No behaviour change to any existing public API. The proof is that
   upstream's own pytest and behave suites pass unmodified.
2. **Refusal atomicity.** Validate fully, then mutate — never mutate then validate. Every
   documented refusal needs a test asserting both that the typed refusal (a
   `docx.errors.PaperRefusal` subclass) is raised and that output bytes equal input bytes.
3. **The reopen rule.** Assertions about document content go save → reopen → assert. Never assert
   on the in-memory object you just mutated; the classic silent failure is an edit that lands in
   the tree and never reaches disk.
4. **Changed-part budgets.** Contract tests assert exactly which package parts an operation may
   touch. A one-paragraph edit that dirties sixty parts is a bug even if the output renders.
5. **No fix without a fixture.** A bug fix arrives with a fixture or golden that fails before it
   and passes after.
6. **No new runtime dependencies.** Dev and test dependencies are negotiable; runtime ones are
   not.
7. **Whitespace is content.** Meaningful text whitespace — including a trailing space inside a
   run — survives every code path. `w:t` and `w:delText` carry preserved-space semantics, and a
   canonicaliser that trims one will make `patch_save` "restore" original bytes over a real edit.

Never reformat an upstream file. Formatter sweeps are scoped to new files; when touching an
inherited file, match the style already there.

## Where things live

| Path | What it is |
|---|---|
| `src/docx/` | the package. Import name `docx` |
| `src/docx/oxml/AGENTS.md` | **read before adding XML vocabulary** — the descriptor system, `successors=`, `r:id` indirection |
| `tests/paper/` | everything this fork adds. Upstream's suite is the rest of `tests/` |
| `tests/paper/fixtures/`, `fixtures_authoring/` | fixture corpus; never regenerated by code under test |
| `tests/paper/golden/` | expected outputs |
| `tests/paper/harness/` | the shared oracle — `checks.py` scans raw zip members for broken relationships, `contract.py` holds the contract assertions, `pkgdiff.py` the part budgets |
| `tests/paper/test_api_surface.py` | pins the exact approved signature of every public function |
| `features/` | upstream's behave suite; proves upstream stays green |
| `docs/dev/analysis/` | **required reading, see below** |
| `tools/` | one-shot maintenance scripts |

New tests go under `tests/paper/`, kept cleanly separate from upstream's suite.

## Read the analysis notes before adding XML vocabulary

`docs/dev/analysis/` holds 35 `.rst` files under `features/` and `schema/` — the only reST left
in the repository, guarded by `tests/paper/test_docs_tree.py`. They are python-docx's own
per-feature design notes, inherited with the fork and never modified. Each
pairs prose with a real XML specimen and the matching xsd excerpt, so they document the OOXML
format and how the oxml layer models it — the layer this fork does not change.

**Read the note for the feature area before implementing anything in `src/docx/oxml/`.** Then
follow the commit shape those features used: analysis → oxml classes → proxy → tests.

`docs/dev/analysis/features/text/font.rst` and its neighbours are the pattern. The xsd excerpts are what a
`successors=` list has to match; get the child order wrong and you produce a file this library
opens and Word rejects.

## Documentation

- **Docstrings are the source of truth for API semantics.** They ship in the wheel and are the
  only documentation that reaches an agent sandbox, so a wrong docstring is an authoritative
  wrong answer given offline with nothing to contradict it.
- They must stay **self-contained and MDX-safe**: no reST substitutions (`|None|`), no Sphinx
  roles (`:meth:`), OOXML tags backticked (`` `w:p` ``), no bare `{…}`. The published API
  reference is generated from them, and a raw `<w:p>` is parsed as a JSX component and fails that
  build. `tests/paper/test_docstring_hygiene.py` enforces this;
  `tools/docstring_hazards.py --fix` repairs it.
- The published site is [docs.paperinstruments.com](https://docs.paperinstruments.com/docs/docx),
  built from `paper-office-docs`. Its `docx/api/` section is generated from these docstrings;
  never edit generated MDX, fix the docstring.
- Each of the fifteen paper-added modules declares `__all__`. It is read by `griffe check` and by
  the docs generator, so a public name missing from it is invisible to the API gate and absent
  from the reference. `tests/paper/test_public_surface.py` enforces it, and pairs with
  `test_api_surface.py`: that one pins signatures, this one pins what is public at all.

## The public API gate

CI runs `griffe check` against the pull request's **merge base** — not the last release tag. It
asks the question rule 1 asks: does this change break the public API? A release-tag baseline
would re-report breakages already accepted on the branch and fail every PR.
